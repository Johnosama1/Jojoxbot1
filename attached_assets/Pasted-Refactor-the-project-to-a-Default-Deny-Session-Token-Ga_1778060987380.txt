Refactor the project to a Default-Deny + Session Token Gate. No feature (bot or Mini App) is accessible unless a fresh server-side verification succeeds.

================================
CORE PRINCIPLE (DEFAULT DENY)

- All requests are BLOCKED by default.
- Access is granted ONLY after successful verification.
- Do NOT rely on previous state (tasksCompleted alone is NOT enough).

================================
STEP 1: CENTRAL VERIFY FUNCTION

Create:

async function verifyUserAccess(userId) {
const user = await db.getUser(userId)

if (!user || user.tasksCompleted !== true) {
return { allowed: true } // no enforcement before tasks
}

for (const ch of requiredChannels) {
const m = await getChatMember(userId, ch.id)
if (!["member","administrator","creator"].includes(m.status)) {
return {
allowed: false,
missing: { title: ch.title, link: ch.inviteLink }
}
}
}

return { allowed: true }
}

================================
STEP 2: HARD GUARD FOR BOT

- REMOVE any direct handlers that run logic immediately.
- Create a single guard:

function guard(handler) {
return async (ctx) => {
const userId = ctx.from.id
const res = await verifyUserAccess(userId)

if (!res.allowed) {
  await ctx.reply(
    `You left a required channel: ${res.missing.title}\nRejoin to continue.`,
    { reply_markup: joinButtons(res.missing.link) }
  )
  return // STOP everything
}

return handler(ctx) // only here logic runs

}
}

- Wrap ALL entry points:

bot.on("message", guard(mainMessageHandler))
bot.on("callback_query", guard(mainCallbackHandler))
bot.command("start", guard(startHandler))

- There must be NO handler outside guard.

================================
STEP 3: MINI APP MUST USE TOKEN

DO NOT allow Mini App to open directly.

Create endpoint:

POST /api/issue-session

Input: Telegram initData
Steps:

1) Validate initData (Telegram auth)
2) Extract userId
3) Call verifyUserAccess(userId)

IF not allowed:
return 403 with { missing channel }

IF allowed:

- Generate short-lived token (JWT or random string)
- Store in Redis/DB with TTL = 30–60 seconds
- return { token }

================================
STEP 4: PROTECT ALL APIs

Every API must require the token.

Middleware:

async function requireSession(req, res, next) {
const token = req.headers["x-session-token"]
const session = await store.get(token)

if (!session) {
return res.status(401).json({ error: "Unauthorized" })
}

req.userId = session.userId
next()
}

Apply to ALL routes:
app.use("/api", requireSession)

================================
STEP 5: MINI APP FLOW (FRONTEND)

On load:

1) DO NOT render UI
2) Call POST /api/issue-session with initData
3) If 403:
   - Show blocking screen:
     "You must join: <channel>"
   - Show Join + Retry buttons
   - STOP
4) If success:
   - Save token
   - Attach token to all API calls (header)
   - Render app

================================
STEP 6: ANTI-BYPASS

- Even if user opens bot deep link → guard blocks
- Even if user opens Mini App directly → no token → blocked
- Even if user was valid before → token expires → must re-verify

================================
STEP 7: DEBUG (MANDATORY)

Log:

- userId
- channelId
- membership status
- when issuing tokens
- when blocking access

================================
RESULT

- Bot: no command works without verification
- Mini App: cannot load without fresh server approval
- Leaving channel = instant block everywhere
- Rejoining = instant restore after retry
